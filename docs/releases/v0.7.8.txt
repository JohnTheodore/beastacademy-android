Beast Academy Android 0.7.8 — release validation
===============================================
2026-10-19. Version code 15. Incremental compatibility release; the holistic
touch-reliability plan and recurring Vanadium freeze remain unresolved.

Behavior
--------
Registers a dedicated input module at document start on each main WebView.
Initial navigation, reloads and replacement documents get fresh installations;
same-document routing retains the installation. No page-finished timing loop.

For qualified v12.119.0 Banvas variants 54145 and 55417, the module excludes
previously observed ended contacts from the engine's event facade and associates
an accepted single-piece gesture with its owning finger. Other fingers cannot
move or finish it. Raw browser events and unrelated controls remain unchanged.
Cancellation and lifecycle interruption clear shared engine tracking without
synthesizing an ordinary release. This does not clear every tool's private state.

Unknown/mixed deployments, changed engine signatures and replaced input helpers
decline adaptation. Reused hosts recheck coordinate/listener dependencies.
Original site handling remains available; this fallback loses the added
protection and is not evidence that the new website version is touch-reliable.
Provider registration failures are recorded without blocking site navigation.
Private diagnostics record compatibility status and document identity.

Open gates and next work
------------------------
1. Per-tool noncommitting cancellation, saved-state/undo preservation and next
   gesture behavior remain unfinished. The fixture deliberately demonstrates
   that a view can remain "moving" after shared engine cleanup. Do not replace
   this work with ordinary release callbacks or whole-lesson state restoration.
2. Drawing/slider corrections, broader custom-control behavior, runtime engine
   selection, real multifinger tools and full asset acquisition/index automation
   remain incomplete. The 194-entry registry map is dependency coverage only.
3. Compatibility limitations are captured privately; a user-visible status path
   remains outstanding. Safe nonactivation does not satisfy the reliability goal.
4. The actual Vanadium 155 trigger has not been reproduced/prevented on a matching
   provider. Real lesson answers, clicks/scrolling, interruptions and subsequent
   play require an authorized isolated lesson session and affected-provider checks.
5. Physical deployment and everyday user validation have not occurred. Preserve
   the existing lesson and capture evidence before any later authorized update.

Do not mark the plan complete or close issue #1 based on this release.
